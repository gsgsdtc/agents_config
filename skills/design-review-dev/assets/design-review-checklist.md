## 2b. 前端代码验证检查

> 适用于：frontend-design

### 2b.1 组件结构验证
- [ ] 组件层次清晰（页面 → 区块 → 基础组件）
- [ ] 组件命名规范（PascalCase，语义化）
- [ ] 共享组件与页面专属组件区分明确
- [ ] 共享组件放置在正确的公共目录
- [ ] 组件职责单一，无过大的 God Component

### 2b.2 状态管理验证
- [ ] 状态分层合理（服务端/URL/表单/UI/全局）
- [ ] 无过度全局化（能局部解决的不上提到全局）
- [ ] 服务端状态使用合适的缓存策略（SWR/React Query）
- [ ] URL 状态用于可分享/可书签的参数
- [ ] 表单状态管理方案明确（受控/非受控/表单库）

### 2b.3 路由与导航验证
- [ ] 路由表覆盖所有设计中的页面
- [ ] 路由路径无冲突（动态路由与静态路由）
- [ ] 受保护路由的权限检查明确
- [ ] 导航流程与设计文档一致
- [ ] 404/403 等错误页面有处理

### 2b.4 数据获取验证
- [ ] API 依赖列表完整（端点/方法/触发时机）
- [ ] SSR/CSR 选择有合理依据
- [ ] 加载态（Loading/Skeleton）有设计
- [ ] 空数据态有设计
- [ ] 错误态有设计（含重试策略）
- [ ] API 端点在后端设计中存在或已实现

### 2b.5 响应式设计验证
- [ ] 断点策略明确（mobile/tablet/desktop）
- [ ] 关键页面有各断点下的适配说明
- [ ] 导航组件在移动端有适配方案

### 2b.6 后端一致性验证（有配对后端设计时）
- [ ] API 路径与后端设计一致
- [ ] 请求/响应数据结构与后端设计匹配
- [ ] 错误码覆盖后端定义的所有错误码
- [ ] 分页/排序等查询参数与后端一致
